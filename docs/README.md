# OctoAcme Project Management Docs

This README is the central index for OctoAcme's project management process documents. It provides a short overview of our approach and direct links to each process document in the docs/ folder to help contributors and stakeholders find relevant guidance quickly.

## Overview (brief)
OctoAcme runs projects with a customer-first, iterative delivery mindset and clear ownership. Projects start with a concise Project Charter and follow a lifecycle of Initiation → Planning → Execution & Tracking → Release → Retrospective. Teams break work into shippable increments, define acceptance criteria and a Definition of Done (DoD), and keep risk registers and release plans up to date to align scope, timeline, and responsibilities.

## Key workflows and roles
Planning uses prioritized backlogs, timeboxed sprint/iteration planning, and a backlog-item template (title, description, acceptance criteria, priority, estimate, owner). Core roles include Project Managers (coordinate delivery and communication), Product Managers (define outcomes and prioritize), Developers (implement and test), and QA (validate acceptance). Day-to-day tracking uses a project board (Backlog → Ready → In Progress → In Review → QA → Done) and a disciplined pull-request workflow with CI, small PRs, and required approvals.

## Quality, communication, and continuous improvement
Testing standards include unit, integration, and end-to-end smoke tests, with security scanning in CI and manual QA when needed. Communication cadence combines daily standups, weekly PM+PdM syncs, and monthly stakeholder updates; escalations follow a tiered path (team → PM/Product Lead → sponsor). Retrospectives capture lessons and action items to drive continuous improvement.
